Foundations

six findings, ranked by blast radius

These aren't hypothetical. Each one is something the system actually did during this session — a request that could approve itself, a route that silently blocked the wrong staff, a notification that needed a manual refresh. Fixing the pattern once is cheaper than finding each instance again.

The rule this session shipped for Overtime — already correct in Leave, missing in Overtime until now. Nobody approves their own tier. The only override is System Admin.
Critical High effort

Seven approval flows, seven separate implementations

Leave, Overtime, Material Requests, Cash Requests, Vehicle Rental, Fuel, and Transport Requests each hand-roll their own "who can act on this stage," "what's next," and "who gets notified" logic. The same three bug classes — a self-approval loophole, a stalled realtime notification, a route mounted in the wrong order — had to be found and patched separately in more than one of them this session.

FixOne shared workflow engine — stage list, actor resolver, transition notifier — that every request type configures instead of reimplementing. Closing a bug class once instead of per-module.
High Medium effort

Site/Client standardization is roughly two-thirds done

Tickets, Material/Cash Requests, Overtime, Project Requests, and Field Work now point at a real site_id. Fuel Requests, Vehicle Rental, and NOC Incident Notes still store site and client as typed text — invisible to Site 360 and Global Search, and open to the exact drift problem the standardization was meant to close (the same site logged three different ways).

FixThe reusable pieces already exist — the same Site search component and search endpoints built this session for Material Requests and Transport. Wiring the remaining three is integration work, not new invention.
Critical High effort

No automated coverage on the paths that move money and approvals

Every fix this session was verified by hand: mint a token, call the API, check the database, delete the test row. That's real verification — but it doesn't persist. Nothing stops the self-approval loophole, or the route-shadowing bug that recurred twice in one session, from quietly coming back on the next change.

FixStart narrow: integration tests over the approval engines and route-mount order, not full coverage everywhere. The highest blast-radius paths — cash execution, approval chains — are worth more test weight than anything else in the system.
High Low effort

Route order is a live footgun, not a one-time mistake

Express matches the first mounted prefix. /api/hr mounted before /api/hr/overtime silently applied HR-only middleware to a route meant for any staff member — and that exact class of bug showed up more than once this session, in different modules, before anyone noticed the symptom.

FixEnforce most-specific-prefix-first as a lint rule or a small route registry, so it's structurally impossible rather than a thing to remember.
Medium Low effort

Notifications need three call sites to agree, every time

A correct notification is an in-app record, a realtime socket emit, and a push send — miss the socket emit and the page just looks stale until someone manually refreshes. That's precisely what the Leave feature did before it was patched to match the pattern Overtime got right from the start.

FixMake the existing shared notifier the only legal way to notify anyone — no module re-pairs the three calls by hand again.
Medium Low effort

The dev environment can go down for reasons that have nothing to do with the app

The Vite dev server crashed twice in this session from an uncaught file-watcher error on a sibling git worktree's lock file — a tooling artifact, not an application bug, but indistinguishable from one until someone reads the stack trace.

FixExclude tooling directories (worktrees, lock files) from the dev server's file watcher. Small, but it removes a whole category of false "why is the app down" moments.

Bets worth pitching

built on infrastructure that already exists

None of these start from zero. Each one leans on something already shipped this session or earlier — the Site 360 aggregation layer, the reference-linking registry, Vobi's live feed, the PDF pipeline — so the pitch to leadership isn't "give us six months," it's "we already built the foundation."

01

One inbox for everything waiting on you

Right now a manager checks Leave, Overtime, Material, Cash, Vehicle, Fuel, and Transport approval queues one at a time. A single "My Approvals" view — aggregating every pending action across all seven, reusing the exact registry pattern built this session for Global Search and Site 360 — is the one change every approver in the company would notice on day one.

Why this landsIt's the cheapest big win on this list: no new data model, no new permissions — just one screen that reads what already exists across seven modules.
High impact Low–medium effort
02

Executive Command Center

A live, role-gated dashboard on top of the Site 360 layer: ticket density by region, SLA-breach forecasting, overtime cost trend, and requests stuck longer than usual at a given stage.

Why this landsIt's the screen a CTO opens in a board meeting.
High impact Medium effort
03

A health score, per site

Site 360 already has every touchpoint a site generates. Rolling that into one score — ticket frequency, incident recency, OT load, SLA compliance — turns an account review from a hunch into a number.

Why this landsSales and account teams get a data-backed answer to "is this client site actually healthy?"
Medium–high impact Medium effort
04

Vobi starts flagging anomalies, not just narrating

The live ops feed already tells the story of what happened. The next step is judgment: "Site X — three fault tickets in seven days," "OT spend up 40% this month," "cash request velocity 2× normal for this region."

Why this landsSame Gemini pipeline already running — this is a new prompt, not a new system.
High impact Medium effort
05

Field app that survives a dead signal

Field engineers already do GPS check-in. Making that installable and offline-capable — actions queue on a dead signal, sync the moment it returns — is a visible, concrete win for crews working sites with patchy coverage.

Why this landsIt's the difference between "the app doesn't work at the tower site" and it just working.
High impact Medium–high effort
06

KPI packs that show up in leadership's inbox

The PDF pipeline already built for payslips, leave, and overtime can just as easily generate a weekly or monthly leadership pack — OT spend by department, SLA compliance by unit, transport utilization — and email it automatically.

Why this landsNear-zero new UI, and it's the kind of thing that gets forwarded to the board.
Medium impact Low effort

Where I'd start

The approval-inbox and the shared workflow engine are the two highest-leverage moves on this whole page — one is the most visible thing you could ship next, the other is what stops today's bug classes from coming back. Everything else compounds on top of those two.

Nothing above is invented for effect: every finding is something the system actually did this session, and every bet reuses something already built rather than proposing a new foundation.
